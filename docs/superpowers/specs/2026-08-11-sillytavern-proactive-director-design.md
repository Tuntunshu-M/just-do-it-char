# SillyTavern 主动导演扩展设计

## 1. 目标

构建一个可通过 GitHub 仓库链接安装的 SillyTavern 前端扩展。扩展在角色扮演期间使用独立副 API 或复用 SillyTavern 当前连接，生成幕后事件计划、判断用户反馈并把精简行动提示临时注入下一次正文生成，让角色以符合自身人设的方式主动带领用户推进剧情。

扩展首版覆盖三类可独立启用的事件：生活日常、突发危机、色情向。完整剧本只保存在扩展状态中，用户可在导演台查看和调整；实际角色回复仍由 SillyTavern 当前主连接生成。

核心约束：

- 不修改角色卡、作者备注或角色人格。
- 不给所有角色追加统一的主动、强势或热情性格。
- 每个关键行动必须有对应角色的人格证据。
- 一条主事件获得主动推进权，其他事件只能作为伏笔等待提升。
- 默认支持单角色卡和一张卡内包含多个人物；暂不支持 SillyTavern 原生群聊。
- 用户可随时暂停、停止、改线、重抽、导入或导出导演状态。

## 2. 技术方案

采用纯前端 SillyTavern 扩展和结构化导演状态机，不要求额外服务端。

副 API 负责：

- 识别人物与人格证据。
- 生成完整事件、阶段、分支和伏笔。
- 判断用户对当前步骤的反馈。
- 根据反馈与人物性格调整后续剧本。
- 输出用于下一次正文生成的精简行动指令。

本地扩展负责：

- 触发调度、状态持久化和请求去重。
- 用户意愿、危机权限、安全词与硬禁区的确定性检查。
- 结构化响应校验和人格一致性校验。
- 临时提示词注入和 SillyTavern 正文生成触发。
- 导演台、设置、副本迁移、诊断和恢复。

完整剧本不会永久写入聊天上下文。每轮只注入当前目标、相关人物依据、本轮行动、连续性事实和边界要求。正文生成结束后移除临时注入。

## 3. 模块边界

### 3.1 Extension Core

接入 SillyTavern 生命周期、当前聊天、消息事件、扩展设置和生成钩子。所有宿主接口集中封装在兼容适配层中。

### 3.2 Context Collector

按以下优先级收集导演上下文：

1. 用户为当前卡填写的导演备注。
2. 角色卡设定与禁忌。
3. 示例对话。
4. 当前聊天中的稳定表现。
5. 副 API 的弱推断。

默认上下文还包括作者备注、最近可配置数量的消息、事件历史摘要、当前步骤、用户偏好和已授权边界。用户可分别关闭角色卡字段、作者备注、聊天历史和世界书内容的发送。

### 3.3 Director Client

支持两种连接：

- 复用 SillyTavern 当前连接。
- 独立 OpenAI Chat Completions 兼容接口，配置 Base URL、API Key、模型、温度、最大输出、自定义请求头和附加请求参数。

可用时默认优先独立副 API，也允许用户手动指定连接。未配置独立副 API 而复用当前连接时显示原文提醒：

> 正在在用主api哦！

用户确认后，本地记录下次提醒时间，24 小时内不再提醒。该状态不进入聊天和副本。

### 3.4 Event Engine

管理一条主事件、伏笔队列、步骤、分支、冷却、触发模式、事件权重和提交事务。主事件暂停、结束或到达合适节点时，导演才能提升伏笔。

### 3.5 Policy Engine

在调用副 API 前后执行本地权限检查。模型输出不能覆盖用户主导权、危机授权、安全词、硬禁区、停止状态或事件类别开关。

### 3.6 Prompt Injector

将当前步骤的精简行动指令临时加入下一次 SillyTavern 正文请求。注入内容明确要求正文模型保持原卡口吻，不提及导演、步骤、剧本或插件提示。

### 3.7 Director Console

提供当前事件、伏笔、人物、偏好与边界、连接与诊断五个标签页，并提供暂停、继续、立即停止、下一步、重抽、改方向、结束、手动创建、导入、导出和撤销导入。

### 3.8 Snapshot Manager

处理聊天级导演副本的导出、导入、分支复制、迁移预览、人物映射和目标状态备份。

### 3.9 Theme Manager

提供稳定的 CSS 变量、插件专属类名、自定义 CSS 编辑、即时预览、启用开关和恢复默认。所有自定义样式默认限定在插件根容器内，避免影响聊天正文或其他扩展。

## 4. 状态模型

每个聊天独立保存 DirectorState：

```text
DirectorState
├─ schemaVersion
├─ chatId
├─ characterFingerprint
├─ cast
│  ├─ castMode: single | multi
│  ├─ members[]
│  └─ lastAnalyzedCardFingerprint
├─ characterProfileSnapshot
├─ activeEvent
│  ├─ category / premise / goal
│  ├─ status / riskLevel / currentStep
│  ├─ steps[] / branches[]
│  ├─ leadCharacter / participants / absentCharacters
│  ├─ characterGoals / conflicts / secrets
│  ├─ personalityEvidence[]
│  └─ compactInjection
├─ foreshadowing[]
├─ eventHistorySummary
├─ userPreferenceState
├─ sceneSafetyState
├─ pendingTransaction
└─ timestamps / cooldowns / counters
```

全局仅保存 API 配置、默认触发设置、默认偏好、UI 状态和用户自定义 CSS。API Key 不进入聊天元数据、调试日志或副本。自定义 CSS 属于本机 UI 偏好，默认不随聊天副本迁移。

## 5. 多人卡适配

多人卡指一张角色卡内部定义多个角色，与 SillyTavern 原生群聊不同。首版支持前者，检测到原生群聊时暂停导演生成和事件推进，但允许查看设置与导出副本。

首次分析角色卡时，副 API 自动识别人物。低置信度时默认按单人卡运行并提示用户校正。用户可手动切换多人卡模式。

每个人物独立保存：

- 姓名和别名。
- 核心、次要或背景 NPC 身份。
- 人格证据、稳定特征和推断置信度。
- 与其他人物及用户的关系。
- 当前状态和人物专属历史。
- 人工修正锁定状态。

人物标签页允许增删、合并、拆分、改名、设置别名、调整关系、选择默认主导角色、锁定人工修正和重新扫描差异。

每个步骤指定主导角色、参与角色和暂不登场角色。甲的人格证据不能用于乙；无法归属的内容标记为共享背景或待确认。主导者可以轮换，但必须符合动机、位置和信息状态，并记录切换原因。正文仍由当前角色卡的一次主 API 请求生成，并保持原卡的多人输出格式。

## 6. 触发与主动联系

用户可选择三种触发模式：

- 混合智能：结合消息间隔、剧情停滞、事件状态、冷却和随机权重，本地未命中时不调用副 API。
- 固定轮次：每 N 次用户消息调用一次。
- 逐轮判断：每次用户消息都调用副 API。

三种模式都支持立即生成事件。

用户可选开启空闲主动联系，并配置空闲时长、冷却、每日上限和允许时段。自动发送前检查当前聊天、页面可见性、生成状态和用户是否正在输入。危机和色情事件默认不能由空闲计时直接开启，只能延续已开始事件；用户可分别放开该权限。

空闲主动联系依赖 SillyTavern 页面保持打开，纯前端扩展无法在页面关闭后可靠唤醒。

## 7. 导演流水线

### 7.1 收集与触发

用户发言后，Context Collector 收集所需上下文，Event Engine 根据当前触发模式决定是否调用副 API。同一聊天最多同时执行一个导演请求，后续触发合并处理。

### 7.2 用户反馈分类

副 API 将回复分类为接受、犹豫、协商或替代、角色内反抗、明确拒绝、场外停止、安全词或无法判断，并返回原文依据和置信度。安全词和场外停止优先由本地规则匹配。低置信度按更尊重用户意愿的类别处理。

### 7.3 结构化导演结果

导演响应遵循 JSON Schema，至少包含：

- 事件类别、前提、目标和风险等级。
- 阶段、当前步骤和可观察分支条件。
- 各人物目标、人格依据和参与职责。
- 对用户反馈的判断与依据。
- 下一轮精简行动指令。
- 伏笔、冷却和结束条件。
- 所需授权或待询问项。

事件计划可在关键回复后继续、软化、改线、暂停或结束，不一次写死。

### 7.4 人格一致性校验

每个关键行动至少引用一条对应人物的有效证据：

- 明确设定：角色卡直接说明。
- 行为证据：示例对话或多轮聊天稳定表现。
- 弱推断：副 API 根据有限信息推断。

弱推断不能覆盖明确设定。行动与高优先级设定冲突时，携带冲突原因自动重试一次；再次失败则不注入正文，并在导演台显示人格依据不足。

主动方式始终服从人设。温柔、强势、冷淡、内向或被动人物使用各自可信的表达与行动方式。用户主导权只决定可推动程度，不决定角色语气，也不能把角色统一改造成强势模板。

### 7.5 注入和提交

通过 Policy Engine 后形成待执行事务，Prompt Injector 注入当前行动，随后自动调用 SillyTavern 正文生成。只有正文成功且确实执行相关行动后才提交步骤。

正文失败、中止、切换聊天或未执行导演行动时不提交。后者由导演选择自然重试、改线或等待下一轮，避免机械重复。

## 8. 用户主导权

用户主导权范围为 0 至 100，并允许聊天级覆盖全局默认：

- 80 至 100：明确拒绝后必须改线；角色可按人设表达感受或再次温和提议。
- 40 至 79：角色可按人设争取、协商或提出一次替代；再次拒绝后改线。
- 0 至 39：普通虚构剧情中，符合人设的角色可坚持安排、制造时间压力或推动既定计划，但不能伪造用户已同意，也不能替用户描述内心、台词或最终选择。

场外停止、立即停止和安全词不受滑块影响。

## 9. 事件类别与危机权限

生活日常、突发危机、色情向分别提供开关和权重。权重仅在已开启类别间归一化，并结合上下文过滤。全部关闭时不自动创建新事件，但仍可手动创建，并可暂停或结束现有事件。

危机分为两层：

- 叙事可控：默认允许，包含行程变化、天气、误会、争执、短暂失联、轻伤和可恢复损失。
- 重大后果：死亡、永久伤残、怀孕、生育、重大疾病、长期失踪、永久关系破裂和巨额财产变化分别设置为禁止、事前询问或已授权。

事前询问在导演台完成，未确认前改走可恢复分支。重大后果授权只对当前聊天有效，不随副本自动迁移。即使已授权，也必须符合人设、因果和已有剧情，不能随机制造灾难。

不可抗力必须具有先兆、因果和可恢复路径，不能突然篡改既有事实。

## 10. 色情与高风险 CNC 模式

色情向默认关闭，扩展按成人虚构场景设计，不扫描角色卡年龄字段，也不增加逐角色年龄弹窗。

高风险 CNC 是色情向下的独立开关：

- 首次开启进行一次明确确认，并要求至少设置一个安全词。
- 用户仅需维护安全词和硬禁区，不设置额外的口头反抗分类、行为清单或场景强度授权。
- 开启后，导演可根据上下文、人设和用户主导权，将剧情内口头反抗作为虚构表演继续推动。
- 安全词、场外停止、立即停止和关闭 CNC 始终拥有最高优先级。
- 停止后立即清除待注入内容、停止当前事件，并禁止空闲触发恢复该事件。
- 日志只记录安全词已触发，不记录安全词文本。

安全词和硬禁区可选随副本迁移，但迁移不自动开启 CNC，也不构成新聊天的场景授权。

## 11. 手动创建与修改方向

手动创建事件提供两个入口：

- 用户完整输入事件、目标、起点和必须保留的事实。
- 用户提出简短构想，由副 API 扩展地点、动机、阶段、伏笔、分支和结束条件。

生成后先显示预览。用户可开始、继续扩展、局部修改、保存为伏笔、重抽或取消。用户明确指定的事实优先于 AI 补全，副 API 不能擅自改变。

修改方向支持自然语言，例如保留已发生事实但更换目的地。导演生成修订预览，确认后仅替换尚未发生的步骤，不偷偷改写聊天中已经成立的事实。

## 12. 副本与迁移

每个聊天默认独立。用户可导出 JSON 副本、导入到其他聊天、复制为平行事件，或撤销上次导入。

快捷预设：

- 适配新角色：保留事件框架和非角色专属历史，重新分析新角色。
- 完整克隆：保留全部可迁移内容和当前进度。
- 自定义迁移：分项多选。

可选迁移项：

- 事件框架。
- 非角色专属历史。
- 角色专属历史。
- 原人格推断。
- 用户一般偏好。
- 事件进度。
- 安全词与硬禁区。
- 人物名单、别名与人工修正。
- 人物关系、当前状态与各自历史。

跨卡迁移原人格推断时提供严格遵循新角色、融合参考和原样保留三种模式。原样保留属于高级选项，并持续显示潜在人格冲突警告。任何模式都不写回新角色卡。

人物按姓名和别名匹配，并显示映射预览。未匹配人物可映射到新人物、作为背景 NPC 保留、删除或由副 API 重新编排。

若目标与副本均有安全词，可选择使用副本、保留当前或合并；合并后任一安全词均能停止。API Key、CNC 开关状态和重大后果授权不进入副本。导入前自动备份目标状态。

## 13. 导演台与视觉设计

导演台采用简洁、紧凑的工具型界面，不使用营销式大标题或大量装饰卡片。标签页承载不同工作区，常用状态保持可扫读，危险配置按开关渐进展开。

标签页：

- 当前事件：概览、步骤时间线、当前分支、人格依据、反馈判断、风险和待注入行动。
- 伏笔：成熟度、触发条件、提升、暂停、删除和重抽。
- 人物：人物识别、别名、关系、角色层级、默认主导者和人工校正。
- 偏好与边界：事件开关及权重、用户主导权、危机权限、色情/CNC、安全词、硬禁区和主动联系。
- 连接与诊断：连接切换、连通测试、模型参数、调用统计和脱敏日志。

交互规范：

- 图标按钮使用 SillyTavern 现有图标体系或已提供的图标库，并为不熟悉的图标添加提示。
- 二元设置使用开关，权重和主导权使用滑块及数值输入，模式选择使用分段控件或下拉选项。
- 风险状态使用有限且一致的状态色，不能仅靠颜色传达含义。
- 窄屏中标签页可横向滚动或折叠为选择器，控件文字不得溢出或互相遮挡。
- 危险操作需要明确确认，但不让普通操作被多余弹窗打断。

### 13.1 CSS 自定义

设置区增加 `外观` 页面。用户可以通过两种层级调整 UI：

- 基础主题变量：背景、面板、边框、正文、弱化文字、强调、成功、警告、危险颜色，以及间距、圆角、控件高度和字体大小。
- 高级自定义 CSS：用户可直接填写 CSS，覆盖插件提供的默认样式。

扩展根节点使用稳定标识，例如 `#st-proactive-director`，公开样式类统一使用 `stpd-` 前缀。自定义 CSS 编辑器默认将规则限定到该根节点；用户无需为每条规则手写选择器前缀。插件文档列出受支持的 CSS 变量和稳定类名，内部实现类不承诺兼容。

外观页面提供：

- 启用或停用自定义 CSS。
- 即时预览和保存。
- 格式化编辑内容。
- 恢复默认样式。
- 导入和导出独立的 CSS 主题文件。
- 在预览前保存上一份可用样式，发生严重布局异常时可一键回退。

自定义 CSS 通过独立的 `<style>` 节点注入，只作用于插件根容器。用户显式启用 `允许全局 CSS` 高级开关后，才允许不受根节点限制的规则；界面需警告全局规则可能影响 SillyTavern 和其他扩展。插件卸载、停用或关闭自定义 CSS 时移除对应样式节点。

自定义 CSS 保存在全局扩展设置中，不保存到角色卡或聊天记录。聊天副本默认不携带 CSS；用户可以单独导出和分享主题文件。主题文件只包含主题元数据、CSS 变量和 CSS 文本，不包含 API、聊天、人物或边界数据。

## 14. 错误处理与状态安全

副 API 流程采用生成、校验、待执行、提交四阶段。

- 超时或网络失败：保留状态并允许重试，不自动切换连接。
- 格式错误：自动结构修复一次，仍失败则停止本轮。
- 人格冲突：携带原因重试一次，仍失败则不注入。
- 权限冲突：本地直接拦截，不允许模型重试绕过。
- 独立副 API 失败：提供重试或本次改用主 API；后者必须主动确认并显示指定提醒。
- 切换聊天：取消旧聊天未完成请求，结果不得写入新聊天。
- 刷新页面：恢复已提交状态，丢弃未提交注入。
- 编辑或删除历史：标记连续性待检查，推进前重新分析相关事实。
- 调试日志默认脱敏，不记录 API Key、安全词、完整角色卡或完整聊天正文。

普通重新生成默认沿用同一导演指令。用户可选择重新判断剧情。只提交最终保留的正文；用户编辑后的正文是连续性事实来源。

## 15. 兼容性与性能

宿主 API 调用全部集中在兼容适配层。启动时检测当前角色、聊天、消息事件、临时注入、正文生成、设置存储和弹窗能力。缺失关键能力时禁用对应功能并显示原因。

独立连接首版以 OpenAI Chat Completions 兼容格式为基线。非兼容响应显示脱敏诊断，不猜测解析。

性能控制：

- 最近消息数量、摘要长度、超时和最大输出可配置。
- 人格快照仅在角色卡变化、人工要求重析或证据冲突时更新。
- 同一聊天只执行一个导演请求。
- 空闲触发遵守页面可见性、冷却、允许时段和每日上限。
- 显示调用次数、失败次数、平均耗时、当前连接和接口返回的 token 数据；没有 token 数据时不虚构费用。

## 16. 验收标准

首版至少验证：

- 两种 API 连接及 24 小时主 API 提醒。
- 三种触发模式、空闲主动联系和两种手动创建入口。
- 三类事件独立开关、权重归一化和全部关闭。
- 主事件与伏笔的提升、暂停、结束和重抽。
- 接受、犹豫、替代、拒绝、安全词和场外停止分支。
- 不同用户主导权下，多种人设仍保持自身表达方式。
- 危机重大后果的禁止、询问和授权。
- 色情/CNC 开关、安全词、硬禁区和停止后的不可恢复状态。
- 正文失败、API 超时、错误 JSON、人格冲突和权限冲突。
- 切换聊天、刷新、编辑、重新生成和删除历史。
- 三种副本预设、自定义迁移、安全词合并、人物映射、跨卡人格冲突和撤销导入。
- 单人卡不被错误拆分，多人卡正确识别人物与别名。
- 人工人物修正可锁定，人格证据不跨人物串用。
- 主导人物切换有依据，不在场人物不会每轮强行出现。
- 原生群聊被识别并暂停导演功能。
- API Key 和敏感日志内容不进入副本。
- 桌面与窄屏无文字溢出、控件遮挡或不可操作元素。
- CSS 变量覆盖、自定义 CSS 即时预览、停用、回退、重置和主题导入导出正常工作。
- 默认自定义 CSS 不影响聊天正文、SillyTavern 主界面或其他扩展；关闭插件后样式节点被清理。
