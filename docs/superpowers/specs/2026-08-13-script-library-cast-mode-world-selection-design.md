# 剧本库、人物模式与世界书选择设计

日期：2026-08-13

## 目标

将事件“生成策划案”和“运行策划案”拆成两个明确阶段，并修复多人角色来源只存在于世界书时无法切换群像侧写的问题。

本次改动提供：

- 每个聊天独立保存的多剧本历史库。
- 包含完整大纲、5-7 个阶段、全部拆分步骤、全部规划伏笔和修订记录的剧本详情。
- 由用户点击“开演”后才开始运行的剧本生命周期。
- 可手动切换且保留各自数据的单角色/多角色模式。
- 首次切换多人模式时，由副 API 从角色卡和当前勾选的世界书资料识别人物并生成群像侧写。
- 只读世界书边界，以及“保留勾选/新聊天取消全部勾选”两种选择策略。
- 按仓储、运行控制、列表、详情和各功能子页拆分的模块化实现。

插件仍只负责策划、阶段准备和导演时间注入，不代替 SillyTavern 主模型生成角色正文，不替 user 决定行动或结果，也不把完整未来剧本一次性注入聊天上下文。

## 已确认的产品规则

1. 事件生成成功后创建一份新剧本并自动打开剧本详情，但不自动开演。
2. 同一聊天可以保留多份剧本。
3. 剧本页左侧显示剧本记录，右侧显示当前选中剧本详情。
4. 运行控制位于剧本页顶部的一行工具栏，包括开演、暂停、继续、改变方向和停止。
5. 用户先选中剧本，再点击“开演”，该剧本才成为当前运行事件。
6. 已有剧本运行时开演另一剧本，必须先确认；确认后停止旧剧本、保留旧进度和历史，并从新剧本第一阶段开始。
7. 停止运行不删除历史剧本。
8. 剧本按聊天隔离。切换到另一个聊天时只显示目标聊天自己的剧本；切回原聊天时恢复原聊天的剧本。
9. 人物页提供单角色/多角色手动切换。
10. 首次切换多人模式时立即调用副 API，识别候选人物并生成多人侧写；之后资料或成员变化只标记 stale，用户点击“重新生成侧写”才再次调用。
11. 单人和多人名单都保留。切回单人时选择一个当前主角色；再次切回多人时恢复原多人名单。
12. 任何模式都禁止把人物侧写、剧本、大纲、阶段、拆分步骤、伏笔、修订或运行进度写入世界书。
13. 世界书始终只作为角色与背景资料的只读输入源。
14. “新聊天自动清空世界书”只表示取消插件世界书页面中的全部书籍和条目勾选，不删除或修改酒馆里的任何世界书内容。

## 信息架构与界面

### 事件页

事件页只负责生成新剧本，保留现有生成选项：

- 随机事件或用户指定想法。
- 单一主类型及辅助调性权重。
- 题材、授权、安全设置和导演备注等已有规划输入。
- 生成状态、失败原因和重试入口。

事件页不再展示完整策划案，也不承载暂停、继续、改变方向和停止等运行控制。

生成成功后：

1. 校验大纲、阶段和伏笔结构。
2. 创建状态为 `draft` 的剧本记录。
3. 选中新剧本。
4. 自动切换到剧本页详情。

### 剧本页

原“伏笔”导航改名为“剧本”。页面采用左右布局：

- 左侧为剧本列表。
- 右侧为选中剧本详情。
- 页面顶部为单行运行工具栏。

窄屏下允许列表与详情改为上下布局，但操作顺序和功能不变，且不得出现文字、按钮重叠或横向溢出。

剧本列表每项显示：

- 标题。
- 创建时间或最近更新时间。
- 状态：未开演、运行中、已暂停、已停止、已完成或生成失败。
- 当前阶段摘要（如果已经开演）。

默认选中当前运行剧本；没有运行剧本时选中最近创建或上次选中的剧本。

详情完整展示：

- 完整剧情大纲。
- 主要矛盾、高潮和结局走向。
- 5-7 个阶段及各阶段拆分步骤。
- 多人剧本中各阶段的活跃人物、人物目标、人物行动和角色间互动。
- 全部规划伏笔，包括来源、表面呈现、埋设阶段、回收阶段、回收方式与影响。
- 当前运行阶段和各阶段状态。
- 修订记录。

规划伏笔显示在剧本详情中，但只有满足导演时间条件的伏笔才进入当前运行上下文。展示完整剧本不等于把完整剧本注入主模型。

### 剧本运行工具栏

工具栏保持一行，按当前剧本状态启用适用操作：

- `开演`：仅对未运行或已停止的选中剧本可用。
- `暂停`：仅对当前运行剧本可用。
- `继续`：仅对当前暂停剧本可用。
- `改变方向`：仅对当前运行或暂停剧本可用。
- `停止`：仅对当前运行或暂停剧本可用。

如果选中的剧本不是当前运行剧本，暂停、继续、改变方向和停止不得误操作其他剧本。

开演冲突规则：已有另一剧本运行或暂停时，点击开演必须弹出确认。取消则保持全部状态不变；确认则先把旧剧本标记为已停止并同步进度，再从所选剧本第一阶段开始运行。

### 人物页

人物页顶部增加“单角色/多角色”分段控件，并让模式成为用户明确选择，而不是根据当前成员数量强制覆盖。

单角色模式：

- 显示当前主角色。
- 可以从已识别人物中选择另一名主角色。
- 单人侧写和单人事件提示词只使用当前主角色及允许的共享背景。

多角色模式：

- 不限制角色总数为 2-4 人。
- 显示完整人物列表。
- 允许添加、编辑、移除人物及指定主推手。
- 事件规划仍按既有群像约束，每个阶段选择 2-4 名相关活跃人物，并在全部阶段中合理轮换。

首次从单角色切换到多角色时：

1. 立即保留 `multi` 模式，不因暂时只有一名成员退回单人。
2. 检查副 API 配置。
3. 读取角色卡和当前勾选的世界书条目。
4. 调用多人识别/侧写提示词，从资料中提取角色 A/B/C/D 等人物，并为每人建立独立目标、关系、知识边界和主动推动方式。
5. 成功后用结果建立多人名单和群像侧写。

如果副 API 未配置，保留多人模式并提示“还没连接副 API”，不调用主 API，不清空已有名单，也不退回单人。

首次自动多人侧写之后，以下变化只标记资料为 stale：

- 角色卡资料变化。
- 当前勾选的世界书内容或勾选集合变化。
- 手动添加、编辑或移除人物。
- 主角色或主推手变化。
- 单人/多人模式变化后，当前模式所需侧写与现有侧写不匹配。

stale 状态显示“角色资料有改动，要重新生成侧写吗？”，并提供：

- `重新生成侧写`：用户点击后才调用副 API。
- `暂时不用`：记录当前资料指纹为已忽略，在资料再次变化前不重复提示。

### 世界书页

世界书页继续负责选择哪些既有书籍和条目作为副 API 与导演规划的输入。页面明确显示：插件不会向世界书写入侧写、剧本、阶段或伏笔。

新增“聊天切换时”设置：

- `保留当前勾选`：新聊天继续沿用全局世界书勾选集合。
- `新聊天取消全部勾选`：检测到聊天标识从一个聊天切换到另一个聊天时，把插件设置中的书籍与条目选择清空。

清空的对象仅为插件的选择配置，例如 `settings.context.worldInfoBooks`。不得调用删除世界书、修改条目或覆盖条目内容的宿主 API。

刷新当前聊天、重新打开扩展或控制台重新渲染不算新聊天，不触发清空。选择被清空后，用户可以在新聊天中重新勾选；切回旧聊天不会恢复旧聊天专属勾选，因为该设置明确选择了跨聊天清空策略。剧本和人物侧写仍按各自聊天状态恢复，不受世界书勾选清空影响。

## 状态模型

### 聊天级剧本状态

每个聊天状态新增独立剧本集合：

```js
{
  scripts: [
    {
      id,
      title,
      category,
      premise,
      conflict,
      climax,
      ending,
      steps: [],
      foreshadowing: [],
      revisions: [],
      status: 'draft' | 'running' | 'paused' | 'stopped' | 'completed' | 'failed',
      currentStepIndex,
      createdAt,
      updatedAt
    }
  ],
  selectedScriptId,
  activeScriptId
}
```

`activeEvent` 的运行职责迁移为以 `activeScriptId` 对应剧本为权威来源。迁移期间可以保留兼容映射，但不能长期维护两份可独立变更的完整事件数据。运行状态更新必须通过剧本仓储提交，保证列表、详情和导演运行读取同一记录。

旧聊天中已有的 `activeEvent` 在迁移时转换为一份剧本：

- 有实际运行进度时映射为对应运行状态。
- 没有明确运行状态时映射为 `stopped` 或 `completed`，不得丢失大纲、步骤、伏笔和修订。
- 迁移具备幂等性，不得在每次加载时重复创建历史剧本。

### 人物模式状态

人物状态保留两套可恢复的数据：

```js
{
  mode: 'single' | 'multi',
  singleSelection: {
    characterId
  },
  multiMembers: [],
  primaryDriverId,
  personalityProfile: {
    mode,
    status,
    content,
    citations,
    activeFingerprint,
    ignoredFingerprint
  }
}
```

具体字段可按现有 `cast` 结构兼容实现，但必须满足：切换模式不删除另一模式名单；校正逻辑不得仅因成员数少于二人把用户选择的 `multi` 覆盖为 `single`。

人物资料指纹必须包含当前模式、当前模式所用成员、角色卡资料和已选世界书资料。多人首次自动生成请求需要去重，并在聊天切换时忽略旧请求的迟到结果。

### 世界书选择策略

世界书选择策略属于全局扩展设置：

```js
settings.context.worldInfoSelectionPolicy = 'preserve' | 'clear-on-chat-change'
```

进入聊天时比较前后聊天标识。只有标识实际变化且策略为 `clear-on-chat-change` 时，才清空插件选择并保存全局设置。初始化扩展时没有前一个聊天标识，不应误触发清空。

## 模块边界

实现不得继续把所有逻辑堆入 `index.js`、`director-console.js` 或单个视图文件。必须按现有目录风格拆分为以下职责；实际文件名可以为适配现有命名约定做等价调整，但职责边界不得合并回单个大文件：

- `src/scripts/script-repository.js`：剧本创建、迁移、查询、选中、更新和状态提交。
- `src/scripts/script-runtime.js`：开演、冲突确认、暂停、继续、改变方向和停止。
- `src/ui/views/scripts.js`：剧本页组合入口，不承载仓储和运行规则。
- `src/ui/components/script-list.js`：左侧列表和选中交互。
- `src/ui/components/script-detail.js`：大纲、阶段、伏笔和修订详情。
- `src/ui/components/script-toolbar.js`：单行运行控制和按钮状态。
- `src/cast/cast-manager.js`：纯人物状态转换与兼容迁移。
- `src/director/profile-service.js`：单人/多人侧写请求、去重、指纹和迟到结果保护。
- `src/ui/views/cast.js`：人物模式、侧写状态和成员操作的页面组合。
- `src/ui/views/event.js`：仅负责剧本生成选项和生成状态。
- `src/ui/views/world-info.js`：只读来源选择和跨聊天选择策略。
- `src/state/`：默认状态、迁移和聊天级持久化。

各模块通过明确服务接口通信。UI 不直接复制仓储状态转换；仓储不操作 DOM；运行控制不自行生成 UI 通知；提示词构建不读写持久化状态。

## 提示词与 API 数据流

### 人物侧写

单角色模式使用单人侧写提示词，多角色模式使用群像侧写提示词。群像请求必须读取完整角色卡与用户当前勾选的世界书条目，不得只读取角色卡描述中的角色 A。

多人响应需要提供可编辑的人物数组，并为每人保留：

- 稳定 ID 和姓名。
- 性格、背景、与 user 的关系和态度。
- 当前目标、秘密或执念，以及必须通过 user 才能完成的目标。
- 说话风格和主动推动方式。
- 已知、可感知、合理推断和明确未知的认知边界。
- 与其他人物的关系证据。

不得把组织、地点或没有人物证据的名词直接当作角色。证据不充分的候选可以标为低置信度，但自动结果仍允许用户手动编辑或移除。

### 剧本生成

事件生成根据 `cast.mode` 和当前模式名单真正切换单人/多人两套提示词。请求必须要求并校验：

- 非空的完整剧情大纲 `premise` 或等价规范字段。
- 5-7 个不同阶段，而不是一个拆分步骤。
- 单人 3-5 个、多角色 4-6 个规划伏笔。
- 主要矛盾、高潮事件和结局走向。
- 多人阶段的活跃人物、各自目标与行动、角色间交集和轮换。
- 认知迷雾、去阴谋论、user 能动性和角色主动推动约束。

主类型与辅助调性继续使用已有权重逻辑，且必须实际进入规划请求。日常、危机和亲密特化只能改变节奏与可用行动，不得绕过安全设置或知识边界。

缺少大纲、阶段数量不足、伏笔数量不足或结构损坏时，不创建半成品剧本。系统可以在固定类型选择和同一请求上下文中进行有限结构修复；仍失败则保留原剧本库并显示明确错误。

### 导演时间注入

开演后，运行模块读取当前剧本和当前阶段。完整大纲、未来阶段和未来伏笔只保存在插件聊天状态中。

每次只在宿主正常生成前准备当前允许注入的紧凑指令：

- 当前阶段目标。
- 当前应行动的人物及其已知信息。
- 已满足条件、可埋设或可回收的伏笔。
- user 最新真实反馈及不可替 user 决定的边界。

未到阶段或条件未满足的伏笔不得提前注入。改变方向只能修订当前和未来阶段，不得改写已经发生的事实。

## 世界书只读保证

实现和测试必须证明：

- 不存在把侧写、剧本、阶段、伏笔或进度写入世界书的调用。
- 不调用删除世界书条目的接口处理“清空”。
- 世界书页面所有写操作只修改扩展设置中的勾选数据。
- 角色卡内嵌世界书和用户手工维护世界书保持原样。
- 世界书原文可以作为副 API 输入，但不直接作为角色已知事实；认知迷雾继续生效。

## 样式与 CSS 模板

新增剧本页布局、列表、状态标记、详情分区和单行工具栏样式。需要同时更新：

- 扩展实际运行样式。
- 主题管理器中的默认/作用域规则（如涉及）。
- 用户可导出的 CSS 模板及其中的选择器说明。

桌面端保证左侧列表宽度稳定、详情可滚动、工具栏不换成多行杂乱控件。手机端允许工具栏横向滚动或紧凑显示，不能遮挡详情、把页面跳回顶部或造成世界书展开状态丢失。

## 错误处理

- 未连接副 API：保留用户选定模式，显示“还没连接副 API”，不回退主 API。
- 人物侧写生成中：事件生成被阻止并提示“导演还在看人设”。
- 多人识别失败：保留旧名单和旧侧写；没有旧数据时保留可手动编辑的当前名单。
- 人物资料 stale：不自动调用 API；由重新生成或暂时不用按钮处理。
- 剧本生成失败：不创建空记录，不覆盖已有剧本，不改变当前运行剧本。
- 开演冲突取消：所有剧本状态保持原样。
- 聊天切换时后台请求返回：旧聊天结果不得写入当前聊天状态。
- 聊天状态保存失败：UI 显示失败，不把内存中的半提交状态伪装为成功。

## 兼容性与迁移

- 为新增全局设置和聊天状态字段提供默认值与迁移。
- 旧 `activeEvent` 转换为剧本记录并保留完整内容。
- 旧单人 `cast` 和侧写继续可读；首次进入新人物 UI 时补齐双模式字段。
- 没有 `scripts` 的旧聊天默认显示空剧本库，不共享其他聊天的剧本。
- 现有世界书选择默认采用 `preserve`，避免升级后意外取消用户勾选。
- 导入/导出诊断快照如包含聊天状态，应包含剧本摘要但继续脱敏 API 密钥和世界书原文。

## 自动化验证

至少覆盖以下测试：

1. 生成成功创建 `draft` 剧本、自动选中并请求切换到剧本页，但不自动开演。
2. 剧本大纲字段被强制校验，空大纲不能进入仓储。
3. 同一聊天保存多个剧本，停止不会删除历史。
4. 不同聊天的剧本集合隔离，切回原聊天恢复原数据。
5. 开演将选中剧本从第一阶段设为运行状态。
6. 开演冲突取消不改变状态，确认后停止旧剧本并启动新剧本。
7. 暂停、继续、改变方向和停止只作用于当前运行剧本。
8. 事件页不再渲染完整策划案或运行控制；剧本页完整渲染大纲、阶段、伏笔和修订。
9. 用户可以强制保持多人模式，即使当前只有一名已识别成员。
10. 首次切换多人模式只调用一次副 API，并读取角色卡与当前勾选世界书。

## 非目标

- 不把任何插件生成内容写入或删除世界书。
- 不自动把世界书中的所有名词都纳入人物名单。
- 不限制多人卡总人数为 2-4 人。
- 不自动开演新生成剧本。
- 不在多个聊天间共享剧本历史或人物侧写。
- 不替 user 发送消息或替 SillyTavern 主模型生成角色正文。
- 不在本轮建立跨聊天的全局剧本资料库、云同步或剧本导入市场。
