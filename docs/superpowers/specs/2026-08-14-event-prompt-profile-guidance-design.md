# 通用事件提示词与可选侧写补充设计

日期：2026-08-14

## 目标

本轮发布完成三件事：

1. 消除事件规划提示词中的刑侦题材示例，防止新剧本无依据混入警局、水箱、法医等其他剧本元素。
2. 在全局设置中提供 Gemini 与 Claude 两套独立、可选的人物侧写补充提示词，只影响人物侧写生成。
3. 核验并完成 `2026-08-13-random-event-day-night-css-template.md` 的剩余发布工作。

## 非目标

- 不根据连接模型名称自动启用任何侧写补充。
- 不允许补充提示词替换现有侧写结构、资料权威顺序或 JSON 输出契约。
- 不把补充提示词注入事件规划、阶段准备或用户反馈判断。
- 不改造现有主题系统、随机事件流程或 CSS 模板格式；这些功能只做现状核验与发布验收。

## 通用事件提示词

`src/director/prompts.js` 保留完整 JSON 结构示例，但示例中的阶段标题、角色行为和伏笔连接标题改为无题材语义的结构占位文本。示例不得包含警局、刑侦、水箱、法医、凶手、死者等具体题材锚点。

事件契约增加以下约束：

- 剧情内容只能来自当前角色卡、用户选择的世界书、当前聊天上下文以及本次事件想法。
- 结构示例只说明字段和格式，模型不得复用示例文本作为剧情内容。
- 不得引入来源中不存在的旧剧本情节、人物、地点、道具、案件或伏笔。
- 留空事件想法仍允许模型依据当前资料随机创作，但不能借用无关历史剧本内容。

回归测试直接检查事件 system prompt，确保其包含来源约束，且不包含已知刑侦题材锚点。测试同时确认结构示例仍有阶段、行为、伏笔状态和连接阶段字段，避免为消除语义锚点而削弱输出契约。

## 侧写补充设置

全局设置新增：

```js
profileGuidance: {
  gemini: false,
  claude: false,
}
```

旧设置通过现有默认值合并迁移自动获得两个关闭状态。设置界面新增独立的“侧写”页签，其中包含：

- `Gemini 角色塑造特化` 复选框。
- `Claude 主动表达特化` 复选框。

两个开关互不排斥，允许均关闭、单独开启或同时开启。切换后立即保存全局设置，不改变 API 连接模型，也不自动发起生成。

## 侧写数据流

`index.js` 从全局设置读取两个布尔值，并以标准化的启用项数组传入侧写服务。侧写服务把启用项加入侧写请求的 `intent.profileGuidance`，同时将其纳入侧写来源指纹。

把开关纳入指纹意味着：用户改变补充设置后，已有侧写会按现有机制标记为需要更新，而不会继续被误判为与当前设置一致。重新生成后，新侧写使用当前启用组合。

`profileContract()` 始终先构造现有基础契约，再按固定顺序追加用户提供的原文：

1. Gemini 角色塑造红线与六项自检。
2. Claude 主动性与情感表达要求及六项自检。
3. 两者同时启用时追加冲突解析规则。

冲突解析规则规定：Gemini 模板中的合理边界、尊重 user 自主性、禁止威胁强迫和精神压迫具有最高优先级；Claude 模板中的“直接决定并执行”只能解释为角色主动发起自身行动，不能替 user 决定、剥夺选择或制造非自愿互动。

模板作为源码静态常量保存，保持用户提供文本的内容与顺序，不做模型名称推断或动态改写。

## 隔离与错误处理

`buildDirectorMessages()` 仅在 `intent.type === 'profile-character'` 时读取 `profileGuidance`。其他意图即使意外携带同名字段，也不会获得侧写补充文本。

未知补充项被忽略。缺失、旧格式或非数组的启用项按空集合处理。设置迁移把缺失布尔值补为 `false`，避免旧用户升级后意外启用。

侧写生成失败继续使用现有失败或陈旧侧写处理逻辑，不引入新的降级分支。
